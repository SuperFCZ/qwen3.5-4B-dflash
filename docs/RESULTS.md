# 测试结果

## 测试配置与结论

**性能基线是不启用 DFlash 的原版（ordinary）。** Target 为 Ascend310P W8A8 OM，
DFlash 使用 Chunk Verify，thinking 开启，每轮最多提出 15 个候选。

- 20 条自定义输入中，当前最快的是 **FP16 Draft**：Draft 平均约 **20 ms/次**，相对原版的 **Decode 加速比 1.92×**。
- W4A16、W8A16 runtime、W8A16 离线 NZ 的接受率分别为 **18.96%、21.03%、21.03%**，FP16 为 **20.83%**；量化版本尚未超过 FP16 Draft 的速度。
- FP16 Draft 的 5 个数据集共 2563 条问题完成，512-token 上限下的整体 **Decode 加速比为 2.44×**。

以下数据来自用户提供的设备报告，均为 `PASS_WITH_DIFFERENCES`：
生成完成并纳入性能统计，ordinary token 一致性未通过，任务质量未评估。

## 指标口径

- **Decode 加速比** = Σ ordinary decode-loop 时间 / Σ DFlash decode-loop 时间。
  DFlash 循环包括 Draft、Verify/commit 和调度，不含 Prefill、循环前 context 构建及启动。
- **Generation tok/s** = 实际输出 token / (Prefill + Decode)。此列包含 Prefill，与 Decode 加速比口径不同。
- **接受率** = Σ accepted / Σ proposed；warmup 不参与统计。
- 两模式分别生成自己的输出，EOS 可能改变实际工作量。图级 ms/call 为同步 OM 调用时间；
  Draft 图统计可能包含 Prefill 调用，不能与阶段表重复相加。
- **阶段时延**是平均 ms/次生成；**单次 OM 时延**是平均 ms/call。C16/C64 混合均值不是某档位的独立测量。
