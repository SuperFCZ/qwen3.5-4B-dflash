# A2：真实 gate/up、down 的独立正确性验证

A1 的九种形状已由用户在 310P3 上确认全 PASS。A2 源码已扩展，**设备 build、数值与耗时
仍待服务器执行**。所有新增代码都在本实验目录，Qwen/DFlash 主流程没有接入 custom op。

| 投影（五层各一次） | M | K | N | N tile 数 | K tile 数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| gate/up | 16 | 2560 | 19456 | 304 | 20 |
| down | 16 | 9728 | 2560 | 40 | 76 |

只开放这两个形状组合；不是任意 K/N 的笛卡尔积。沿用 A1 的单核、N64/K128、片上 FP16
反量化、完整 K 的 FP32 累加路径。kernel 源码未改，没有完整 FP16 权重写回 GM，也没有
多核、双缓冲或预取优化。每个 N tile 用户 UB 仍为 24,704 B，MatMul 额外缓冲由 host 查询。

## 数据来源和验收边界

1. `a2_capture.py` 校验固定 W8A16 checkpoint，复用 `load_quantized_draft` 和 `DraftGraph`，
   回放已有 C++ `debug_draft_om.py` 保存的冻结输入：features、标量、五层 KV cache。
   forward hook 保存五层 gate/up、down 的真实输入和 native eager 输出。重复两次，输入/
   输出位型必须稳定，冻结输入必须保持只读。
2. gate/up 权重来自生产 `GroupQuantLinear.concatenate(gate, up)`，前半是 gate，后半是 up。
   signed INT8 NK/NZ、FP16 GN scale 都保存完整 bytes/SHA256；没有重新量化或随机替代。
   scale 从模块 NG 转 GN 只转存储。Target 原始 checkpoint 只读取 anchor/mask 的两个
   FP16 embedding 行，与生产 Draft 使用的 FP16 embedding 一致；不加载 Target decoder/head。
3. `a2_export.py` 为这十组真实权重导出静态 M16 原生 WeightQuant OM。复用生产
   `weight_quant_linear`、offline-NZ AIR 导出/编译入口，`inner_precise=0`、group128，
   `must_keep_origin_dtype`、`deterministic=0`。OM 只暴露 `x -> y`，权重/scale 是不可变常量。
   独立 eager 执行须先与捕获输出一致，防止 scale 存储解释再次错位。
4. `run_a2.py` 校验全部输入/OM 哈希，分别用独立 C++ 进程执行 custom ACLNN、native OM。
   **custom↔native OM 必须 FP16 bitwise 相等，atol=0、rtol=0**；非有限值、重复漂移、越界、
   输入被写、缺少 case 都失败。eager↔OM、少量行列的 CPU FP64 完整 K oracle 只作诊断。

这里的激活来自**真实冻结输入的 native eager DraftGraph 回放**，并非从已编译完整 Draft OM
内部 dump 出来的张量。A2 比较的是相同 X/W/S 的独立投影 OM；完整 Draft OM 中的中间激活、
proposal token、接受率、decode speedup 均不在这次验收内，报告继续保留 `NOT_RUN`。

## 服务器命令

需要现有模型 Python 环境（torch、torch_npu、TorchAir、numpy、safetensors，以及 native
`npu::adn_rms_norm`）、CANN 9.0.0、310P3、真实 W8 checkpoint、原始 Target checkpoint。
使用已有成功 baseline 的环境；不需要安装新的 Python 包到系统环境。

从仓库根目录执行，输出全部放在新的目录中：

```bash
git pull --ff-only
export CANN_ROOT=/usr/local/Ascend/ascend-toolkit/latest
source "$CANN_ROOT/set_env.sh"
export MODEL_PYTHON=/path/to/existing/model/python
export DEVICE_ID=0
export AI_RUN_DIR=/path/to/existing/baseline/run
export DRAFT_DIR=/path/to/Qwen3.5-4B-DFlash-W8A16
export TARGET_DIR=/path/to/original/Qwen3.5-4B
export REPLAY_REPORT=/path/to/debug-draft-xxx/private.json
export A2_ROOT="$AI_RUN_DIR/draft-quant-a2-$(date +%Y%m%d-%H%M%S)"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_capture.py \
  --draft-dir "$DRAFT_DIR" --target-dir "$TARGET_DIR" \
  --replay-report "$REPLAY_REPORT" --device-id "$DEVICE_ID" \
  --output-dir "$A2_ROOT/capture"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_export.py \
  --bundle "$A2_ROOT/capture/manifest.json" --output-dir "$A2_ROOT/native" \
  --atc "$CANN_ROOT/bin/atc" --device-id "$DEVICE_ID"

export A2_BUNDLE="$A2_ROOT/capture/manifest.json"
export A2_NATIVE_OM_MANIFEST="$A2_ROOT/native/native-om.json"
DFLASH_SUITE=a2 bash framework/custom_ops/draft_quant/run_server.sh
```

`--target-dir` 指保留 FP16/BF16 embedding 的原始 Target safetensors，不是 W8A8 的 embedding
二进制目录。默认 tensor key 是 `model.language_model.embed_tokens.weight`，不同 checkpoint
命名可显式传 `--embedding-key`，脚本校验 shape 并记录源 shard SHA256。

`--feature-layers` 必须与生成 frozen snapshot 的 Target 导出顺序相同。默认是 W8 Draft
checkpoint 的五个选定层；若 baseline 使用多 Draft 变体共用的 11 层 feature 输出，在
capture 命令中加入：

```bash
--feature-layers 1,5,8,9,13,15,17,21,22,25,29
```

输入宽度不匹配会直接报错，脚本不会猜测层顺序。如果没有冻结输入，先用已有成功 baseline
的 deployment、runner、prompt 生成一份；这不会重新导出完整模型：

```bash
"$MODEL_PYTHON" tools/debug_draft_om.py \
  --run-dir "$AI_RUN_DIR" --runner "$CPP_RUNNER" \
  --deployment-manifest /path/to/w8a16-offline-nz/deployment-manifest.json \
  --prompt-report /path/to/baseline/prompt-report.json \
  --device-id "$DEVICE_ID" --workspace private --repetitions 2
```

把打印的 `private.json` 路径设为 `REPLAY_REPORT`，不是 `comparison.json` 或分析报告。
capture 校验 `contract.txt` 与 snapshot hash，按报告中实际执行的 16/64 context gear
截取 features（snapshot 本身可能保留 64 行最大分配），并分别记录原始/回放输入 hash；
gate/up、down 投影始终为 M16。
回放在最后一个 down 输出捕获后结束，不需要加载词表 head。

## 报告与耗时

- `capture/manifest.json`：十个 case、输入/输出与权重文件哈希、checkpoint 审计、冻结输入
  身份、embedding 来源、capture 两次重复性。`status=PASS` 只表示采集完成。
- `native/native-om.json`：AIR/deployment/OM 哈希、ATC 命令、相同权重绑定。
  `status=PASS` 只表示十个原生 OM 编译成功。
- `.runs/a2-*/data/suite.json`：十个 case 的最终 A2 状态，任意缺失/失败返回非零。
  **只有 `PASS: 10 A2 real projections` 才表示本次 A2 数值门槛全通过。**
- 各 case 的 `custom/runner.log`、`native_om/runner.log`、`execution.json`、
  `actual-{0,1}.bin`、`comparison.json` 保留具体阶段、错误、bit mismatch、ULP 和首次差异。

两端各先执行两次正确性检查，再 warmup 3 次、测量 10 次；可用 `A2_WARMUP`、
`A2_REPETITIONS` 增加次数。每次输出检查在计时区间之外，所有调用均检查 guards 和输入只读。
同一 case 使用相同设备/输入，两端调用次序按 case 交替。

`timing.execute_sync` 保存 host 发起执行到 stream 同步完成的所有毫秒样本、median、p95。
H2D/D2H、输出 poison、guard/read-only 检查、文件读写、模型加载与 ATC 不计入；
custom 的 `GetWorkspaceSize`/workspace 分配耗时单列 `timing.prepare`。
这些是**带正确性检查的独立调用诊断**，不同 runner 接口开销和检查造成的 cache 状态也会影响
结果，不能作为完整图区域收益或 decode speedup；这里不报告加速比。

custom 记录 ACLNN workspace，native OM 用 `aclmdlQuerySize` 和显式 model workspace/weight
分配记录对应字节。`tracked_device_allocation_bytes` 包括 runner 管理的输入、输出、工作区、
常量和 guards；不包含驱动/框架隐藏分配，**不是进程峰值显存**。后者保留
`process_peak_device_memory=NOT_MEASURED`，完整性能验收仍需设备侧测量。
