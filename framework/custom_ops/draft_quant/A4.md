# A4：全部量化投影与 M16/32/64/80

本阶段扩展 `DFlashGroupQuantLinear` 的形状和独立验收，覆盖一次 Draft 的全部
**1 个 FC + 5 ×（KV、Q、O、gate/up、down）=26 个投影**，分别验证 C16、C64。
生产模型、导出和运行主流程没有接入 custom op。**用户已确认 A4 完整通过，服务器证据目录
为 `.runs/a4-ziy26oQK`；本地未重新审计该目录。完整 Draft / Decode 为 `NOT_RUN`。**
随后发现 KV M80 搬运/时延异常，当前候选和服务器命令见 [A4_1.md](A4_1.md)，尚无候选设备结果。

用户反馈 A3.2 down 约 1.91→1.79 ms，native 约 1.54 ms，详见 [A3_RESULTS.md](A3_RESULTS.md)。
按用户要求暂停该路径的性能优化。本阶段保持其反量化、串行/预取调度、N64/K128 和数值边界；
默认仍为 batched+serial，原有显式 `DFLASH_PIPELINE_MODE=prefetch` 候选保留。

## 固定工作负载

| 投影 | 每档次数 | M（C16 / C64） | K | N |
| --- | ---: | --- | ---: | ---: |
| FC | 1 | 16 / 64 | 12800 | 2560 |
| KV | 5 | 32 / 80 | 2560 | 2048 |
| Q | 5 | 16 / 16 | 2560 | 4096 |
| O | 5 | 16 / 16 | 4096 | 2560 |
| gate/up | 5 | 16 / 16 | 2560 | 19456 |
| down | 5 | 16 / 16 | 9728 | 2560 |

只接受表中完整 `(M,K,N)` 组合；不开放任意笛卡尔积。KV M16/M64、FC M32/M80 和
gate/up M64 均拒绝。合成测试另开放 `M={16,32,64,80} × K={256,512,1024} × N={64,128,256}`
共 36 种形状，包含原 A1 九种。

X/Y 为连续 FP16 ND，W 为 signed INT8 offline-NZ，S 为连续 FP16 GN、group128。
权重/scale 布局和 ACLNN 签名不变。**内部 tiling 新增 `globalM`，必须重新构建 host、kernel、
OPP 和 runner，不能混用旧包。** build/launch 均为 v4，tiling ABI 为 `full-m-v2`；
launch 新增 `tile_m`、`weight_reuse_rows`，均须等于 M。
后续 A4.1 当前构建的 build/launch 为 v5，增加 A source 和 Cube 资源记录，内部 tiling
仍为 `full-m-v2`。当前脚本按构建的实际版本验证；本页 v4 描述用于原 A4 baseline。

## 一份权重 tile 服务全部 M 行

核 b 仍按 `b,b+B,...` 拥有 N64 tile、完整归约 K。单输出块扩展为 `[M,64]`，
`singleCoreM=baseM=M`。每个 group 的 q/scale 只搬入一次、只反量化一次，同一 W16 tile
服务全部 M 行。没有按 M16 子块重启外层 K 循环或无条件重读整张权重。

每次 K128 `Iterate(false/true)` 保留同一 FP32 L0C，全部 K 完成才 `GetTensorC`，只执行
一次最终 FP16 舍入。K256 合成用例仍走整段 `IterateAll`，不做 split-K 或 FP16 部分和。

Host 使用 `SetShape(M,64,tileK)`、`SetOrgShape(M,N,K,tileK)`、`SetFixSplit(M,64,128)`。
SDK 返回的 baseM/singleCoreM 必须为 M、baseN/singleCoreN 必须为 64、流式 baseK 必须
为 128，否则打印实际/预期参数并拒绝，不退回多个 M 输出块。官方 v9.0.0
[Matmul tiling 源码](https://gitcode.com/cann/asc-devkit/blob/v9.0.0/impl/adv_api/tiling/matmul/matmul_tiling_algorithm.cpp)
的固定 M 因子按 C0=16 对齐，并按资源选择缓冲深度；M80 是五个 M16 block。
目标 SDK 是否返回兼容计划仍需服务器验收。

K128 用户 UB 与 M 无关：serial 24,704 B，选中 raw prefetch 为 33,024 B，剩余 UB 分给
Matmul。M 增加的是 SDK 管理的 A/L0C 等资源。以下是单份逻辑 payload，不是全部片上分配：

| M | A（FP16 M×128） | B（FP16 64×128） | C（FP32 M×64） |
| ---: | ---: | ---: | ---: |
| 16 | 4,096 B | 16,384 B | 4,096 B |
| 32 | 8,192 B | 16,384 B | 8,192 B |
| 64 | 16,384 B | 16,384 B | 16,384 B |
| 80 | 20,480 B | 16,384 B | 20,480 B |

Host 日志按实际 Cube depth/db、转排布长度记录 planned L1/L0A/L0B/L0C、用户/Matmul UB
和系统 workspace。不能把上表相加当成 UB 或峰值显存。

## 两档真实数据与 native OM

复用 A2 capture/export，显式增加 `--scope a4`，使用独立 A4 manifest ABI；旧 A2 的十个
case 不能代替 A4。每档都需要真实 frozen replay report，其 `kv_output_audit.context_rows`
分别为 16 和 64。缺少某档时，用 [A2 的 frozen replay 入口](A2.md)、原 baseline deployment
和真实 prompt 重新捕获并检查实际 gear；不要编辑 report、复制/填充激活或改 valid_rows
来伪造另一档。snapshot features 可能保留 64 行最大分配，capture 仍按实际 active gear
取回放行，与原生产约定一致。

capture 使用原 `DraftGraph`、feature layer 顺序及
`torch.ops.npu.npu_scatter_nd_update.default`，无 index_copy、CPU fallback 或替代数学。
钩子依次捕获 FC、五层 KV/Q/O/gate_up/down，最后 down 后退出，不加载词表 head。
每档回放两次，检查输入/输出重复性与冻结源只读；两档要求相同 W8 checkpoint，所有同名
projection 的完整 NK/NZ/scale 哈希及 feature layer 顺序一致。

沿用成功 A2 的 `AI_RUN_DIR`、`MODEL_PYTHON`、`DRAFT_DIR`、`TARGET_DIR`、`CANN_ROOT`、
`DEVICE_ID`。`FEATURE_LAYERS` 取原成功 A2 capture 的 `source.feature_layers`，用逗号连接。
下面 `/path/to/...` 要替换成实际报告路径，所有输出目录必须是新的：

```bash
git pull --ff-only
export C16_REPLAY_REPORT=/path/to/actual-c16/private.json
export C64_REPLAY_REPORT=/path/to/actual-c64/private.json
export A4_ROOT="$AI_RUN_DIR/draft-quant-a4-$(date +%Y%m%d-%H%M%S)"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_capture.py \
  --scope a4 --context-rows 16 --replay-report "$C16_REPLAY_REPORT" \
  --draft-dir "$DRAFT_DIR" --target-dir "$TARGET_DIR" --feature-layers "$FEATURE_LAYERS" \
  --device-id "$DEVICE_ID" --output-dir "$A4_ROOT/c16/capture"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_capture.py \
  --scope a4 --context-rows 64 --replay-report "$C64_REPLAY_REPORT" \
  --draft-dir "$DRAFT_DIR" --target-dir "$TARGET_DIR" --feature-layers "$FEATURE_LAYERS" \
  --device-id "$DEVICE_ID" --output-dir "$A4_ROOT/c64/capture"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_export.py \
  --scope a4 --bundle "$A4_ROOT/c16/capture/manifest.json" \
  --output-dir "$A4_ROOT/c16/native" --atc "$CANN_ROOT/bin/atc" --device-id "$DEVICE_ID"

"$MODEL_PYTHON" framework/custom_ops/draft_quant/test/a2_export.py \
  --scope a4 --bundle "$A4_ROOT/c64/capture/manifest.json" \
  --output-dir "$A4_ROOT/c64/native" --atc "$CANN_ROOT/bin/atc" --device-id "$DEVICE_ID"
```

embedding key 非默认时继续传原 `--embedding-key`。全投影 capture 包含完整 NK/NZ 权重，
随后编译 52 个独立 OM，所需磁盘空间高于原 A2 十个 case。

每个 native OM 仍只接受 `x`，INT8 权重/FP16 scale 为 immutable 常量。保留 FileConstant
descriptor、NZ roundtrip、形状/哈希安全检查、生产 NG-backed scale view、inner_precise=0、
must_keep_origin_dtype、deterministic=0。导出前 standalone native eager 须与捕获输出一致。

## 构建与完整 A4 验收

```bash
export A4_C16_BUNDLE="$A4_ROOT/c16/capture/manifest.json"
export A4_C64_BUNDLE="$A4_ROOT/c64/capture/manifest.json"
export A4_C16_NATIVE_OM_MANIFEST="$A4_ROOT/c16/native/native-om.json"
export A4_C64_NATIVE_OM_MANIFEST="$A4_ROOT/c64/native/native-om.json"
export A2_WARMUP=5
export A2_REPETITIONS=30

DFLASH_SUITE=a4 DFLASH_CORE_LIMIT=0 DFLASH_DEQUANT_MODE=batched \
  DFLASH_PIPELINE_MODE=serial bash framework/custom_ops/draft_quant/run_server.sh
```

脚本创建新 msopgen 工程、隔离 OPP 和 runner，不覆盖生产 OPP，然后运行：

1. C16/C64 完整 capture、checkpoint/权重/scale/feature order 和 native OM 绑定检查。
2. `data/synthetic`：36 种形状、351 个合成 case，含原 A1、M block 边界、所有 K-group
   边界、最后 group、signed zero、dense signed、rounding probe 和 FP32 相消。
3. `data/c16`、`data/c64`：分别 26 个真实 projection 的 custom ACLNN↔native OM 对照。
4. 全部 host launch version 4、M/N/K、full-M 复用、pipeline、core cap/实际核数检查。

硬门槛仍为 **FP16 bitwise equal、bits=0、ULP=0**。非有限值、repeat drift、guards、输入
被修改或缺失 case 都失败。合成 exact case 也检查 CPU oracle；rounding probe 的 CPU
差异只诊断，custom/native 仍逐位比较。真实 case 的 eager/CPU sampled 结果只诊断，
不放宽 native OM 门槛，也不以首 16 行通过代替 M80 通过。

保留 `continuous-v1`、默认 warmup=5/repetitions=30、执行前两次 correctness、timed tail
及 post-poison 检查。GetWorkspaceSize 单列，timed 循环没有 D2H/poison/文件 IO。
capture、native OM、runner 绑定哈希，suite 结束再次检查源文件和构建身份。

完整成功标志为 `PASS: A4 M16/32/64/80; 36 synthetic shapes + C16/C64 52 real projections`。
capture、编译、单个 gear 或最后一个 case 的 PASS 都不是完整 A4 PASS。
主报告 `.runs/a4-XXXXXXXX/data/suite.json` 的 `checks` 定位失败阶段，`launches.c16/c64`
保存每个 case 的 custom/native timing、workspace 和启动计划。具体错误查 case 的 runner.log。

如需复测保留的 A3.2 prefetch，把 pipeline 改为 `prefetch`，仍需完整 A4 验收；它继续只
选择原 down 和流式合成 K512/1024，Q/O/KV/FC/gate_up 均 serial。这不是新的性能优化，
也不自动将候选提升为默认。
